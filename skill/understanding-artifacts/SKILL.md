# Understanding Artifacts

## When to Use
Turn a topic, source, codebase or model output into inspectable explanations: clear writing, a causal diagram, an interactive webpage, and a bespoke narrated video. Use all four for a comparison; otherwise choose the smallest format that answers the learner's question. The outcome is understanding an idea and its limits, not multiplying pretty deliverables.

## Procedure
1. **Lock the learning question.** Identify audience, language, prerequisite knowledge and the decision or prediction a learner should make afterwards. For new visual content, present materially distinct concept options and get a pick. Keep the user's chosen topic through revisions.
2. **Inspect the original sources.** Fetch supplied URLs/files before historical recall. Use terminal HTTP or the browser if web tools lack credentials. Save source URL, retrieval outcome, relevant passage and claim IDs. Separate source facts, computed facts, illustrative assumptions and unknowns. Do not replace inaccessible evidence with fabricated output.
3. **Create one explanation contract.** Use `templates/contract.json`: central question, stable glossary, claim→source map, exact example values, units, caveats and observable visual beats. Calculations come from executable code. All output modes consume this contract; verify equations, narration, labels and interactions agree. Model-measured values and hand-chosen educational values are different evidence types.
4. **Write for comprehension.** Short active sentences; one meaning per sentence; technical terms defined once and used consistently. ASD-STE100-inspired English can be useful. Strict compliance requires the applicable licensed specification, dictionary and qualified checks; sentence-length lint is not certification. “80% STE” means a style preference, not a measured compliance score. Korean uses natural clear writing, not an English standard translated word-for-word. Include an accurate limitation and a small comprehension question.
5. **Draw relationships.** Diagram arrows encode cause, data flow or time and state which. Keep one central example and a stable spatial/color mapping across formats. Expose a misconception by showing a counterexample. Label illustrative schemas. Decorative cards, logos and sentence blocks are not explanatory diagrams.
6. **Build the experiment, not a slideshow.** Deliver runnable HTML with meaningful controls that change the explained phenomenon. Separate pure functions from DOM work and expose them for independent tests. Provide keyboard labels, responsive layout, explicit units, reduced motion and no automatic audio. Prefer local/embedded fonts and no remote dependency. Load `creative-web-artifacts`; use `canvas-motion-graphics` for deterministic `render(t)` animation. Include sources, transcript and a static diagram alternative.
7. **Make a bespoke narrated video.** Load `explainer-video-production` and inspect the installed engine's authoritative API and a real reference example. Default to installed free/local TTS; additional paid APIs require approval. Disclose chosen narration and screen languages. Narration fixes visual timing; cues reveal cause/consequence, distributions evolve, objects persist meaningfully, sampling/feedback are visible events. Mathematical animation can borrow general teaching techniques without copying another creator's identity, logo or voice. Export H264, yuv420p, faststart and a transcript. For direct canvas exports, expose deterministic `render(t)` and use the loaded canvas export workflow. Do not replace this with a static sentence video.
8. **Test in layers.** Run factual/semantic assertions first, then browser unit+interaction tests, offline/no-request smoke, mobile/desktop overflow, keyboard and font checks. Video: run engine check, draft render and full contact-sheet vision review; iterate concrete defects; render final and inspect frames decoded from the final MP4. Run audio loudness, silence/black-frame and speech intelligibility checks when available. Run `scripts/audit_bundle.py` for hashes, local-link presence and actual ffprobe metadata. Its checks establish file/packaging properties, not scientific accuracy, accessibility certification or comprehension.
9. **Review independently.** A separate reviewer reads code/contract, reruns tests and views final screenshots/stills. Parent verifies the reviewer handles and reconciles findings against current artifacts. Write `test-report.json` with real commands, outcomes and limitations. Distinguish technical checks, subjective visual review, user approval and measured learning improvement. No “100% quality” or human-comprehension claims from render success.
10. **Deliver and optionally publish.** Package HTML, diagram, MP4/transcript, contract, sources, tests and portable skill. Exclude secrets, private sources, account/machine paths, logs and third-party cached pages from public packages. Default to local/Telegram delivery. External publishing needs user authorization. For authorized X publishing load the installed X operations skill, confirm the live account, enforce post spacing and stop at login/CAPTCHA/bot gates. Publish a source-backed result with caveats and reproducible prompt; retrieve final permalinks and revisit them. Quote reposting results and plain reposting a source are separate actions; don't claim one proves the other.

## Pitfalls
- Bigger formats are not automatically better. A paragraph can beat a video for lookup; a slider is useful for causal exploration. Report this as a design judgment unless tested on people.
- Probability isn't truth. In generation demos clarify the distinction between next-token likelihood and verified factual correctness. Label fixed educational logits and omitted full vocabulary; don't simulate real autoregressive recomputation with constant values.
- Top-p keeps the smallest sorted probability prefix reaching its threshold, including the crossing token, then renormalizes. It isn't a per-token probability floor. Temperature is positive; greedy is a separate mode. Preserve these semantics across all outputs.
- Rounded percentages may not sum to exactly 100%; distinguish display rounding from numerical normalization errors.
- All alternate-temperature percentages must be computed from the same declared logits. Do not hand-tune chart values to look sharper/flatter without marking a different example.
- For a sample draw, assert the spoken number, pointer coordinate, cumulative interval and chosen label agree. A draw below a 0.731 cutoff cannot choose the second interval. Keep original top-p mass and renormalized sampling intervals visually distinct.
- Browser assertions need actual rendered geometry: nonzero probability-bar area, visible mode controls at mobile width, loaded font faces, and correct active-state styling. Document-level no-overflow alone can miss hidden controls. Do not silence all 404 errors to excuse a pending video; incomplete tests must be labeled incomplete, and the final test requires actual MP4 playback.
- Font presence alone doesn't prove glyph rendering. Inspect actual Korean screen captures. Ensure no automatic playback overwrites manually inspected frames.
- A child claiming upload or completion is not proof. Inspect file, ffprobe, final decoded frame and destination page yourself.
- Unsupported verifier output stays a blocker/limitation. Don't invent speech scores, comprehension gains or paid API usage.
- Dark themes can trigger black-frame detectors on sparse title-only frames. Inspect actual decoded frames before deciding whether a report is a real blank frame or a detector-density artifact; improve empty beats/contrast and rerun rather than silently filtering warnings.
- A single browser page can contain both an inline editor and a delayed compose modal. Wait for the intended container and scope editor, media input and submission button to it. Inspect the real preview; correct text in a background editor does not prove the foreground composer is ready. Record submission attempts and never blindly retry an ambiguous result.

## Verification
Deliver only after source/cross-format checks, pure-function tests, real browser exercises and final visual/audio checks actually run. Record skipped tests explicitly. `scripts/audit_bundle.py ROOT --report PATH` reports packaging/media evidence and exits nonzero for missing assets or invalid video; source accuracy and comprehension remain separate reviews. It checks static resource references, not computed network behavior, so a real browser network-interception test is still required. Run `python3 scripts/test_audit_bundle.py --report regression.json` after changing the auditor; its synthetic fixtures are not real demo or learning measurements. The auditor report is a packaging report, separate from the full `test-report.json` defined in `references/evaluation.md`. The contract template is `templates/contract.json`.
