# 이진 탐색: 정렬된 범위를 반씩 좁히기

## 질문

정렬된 배열에서 원하는 값을 빠르게 찾으려면 어떻게 할까?

## 핵심 규칙

이진 탐색은 **정렬되어 있다는 사실**을 전제로 한다. 현재 후보 구간의 양 끝을 `L`과 `U`로 두고, 중간 위치를 다음처럼 계산한다.

```text
mid = floor((L + U) / 2)
```

`array[mid]`가 목표보다 작으면 왼쪽 절반을 버리고 `L = mid + 1`로 옮긴다. 값이 목표보다 크면 오른쪽 절반을 버리고 `U = mid - 1`로 옮긴다. 같으면 찾은 것이다. `L > U`가 되면 배열에 값이 없다.

## 같은 예시, 두 결과

배열은 `[2, 5, 8, 12, 16, 23, 38]`이고 목표는 `16`이다.

1. 처음 범위는 인덱스 `0..6`이다. `mid = floor((0+6)/2) = 3`, 값은 `12`다.
2. `12 < 16`이므로 인덱스 `0..3`을 버린다. 다음 범위는 `4..6`이다.
3. `mid = floor((4+6)/2) = 5`, 값은 `23`이다.
4. `23 > 16`이므로 오른쪽 인덱스 `6`을 버린다. 다음 범위는 `4..4`다.
5. `mid = 4`, 값은 `16`이다. 목표를 찾았다.

같은 배열에서 목표를 `7`로 바꾸면 다음과 같다.

1. `0..6`의 중간은 `3`, 값 `12`다. `12 > 7`이므로 `4..6`을 버린다.
2. `0..2`의 중간은 `1`, 값 `5`다. `5 < 7`이므로 `0..1`을 버리고 `2..2`만 남긴다.
3. 인덱스 `2`의 값은 `8`이다. `8 > 7`이므로 범위가 비어 `L=3, U=2`가 된다.
4. `L > U`이므로 `7`은 배열에 없다.

## lower와 upper를 구분하기

이 자료의 탐색은 “하나의 목표를 찾는가”를 보여 주는 기본 이진 탐색이다. 중복 값에서 첫 위치와 삽입 위치를 구하려면 경계를 조금 다르게 유지한다.

- `lower_bound` 또는 `bisect_left`: 목표보다 **작지 않은** 첫 위치.
- `upper_bound` 또는 `bisect_right`: 목표보다 **큰** 첫 위치.

따라서 “발견했다”는 한 번의 일치와 “정렬된 구간의 경계”는 서로 다른 질문이다.

## 왜 빨라지는가

매 단계에서 후보 수가 대략 절반으로 줄어든다. 그래서 후보가 `n`개일 때 비교 횟수의 상한은 로그 규모로 증가한다. 배열의 임의 위치를 바로 읽을 수 있다는 조건도 필요하다. 연결 리스트처럼 중간 위치 접근이 비싼 자료구조에서는 이 장점이 그대로 나오지 않는다.

## 짧은 의사코드

```text
L = 0
U = length(array) - 1
while L <= U:
    mid = floor((L + U) / 2)
    if array[mid] == target: return mid
    if array[mid] < target: L = mid + 1
    else: U = mid - 1
return -1
```

## 한계와 확인 질문

이 예시는 교육용으로 고정한 정수 배열이다. 입력이 정렬되어 있지 않으면 버린 절반에 목표가 있을 수 있어 결론을 믿을 수 없다. 중복 값의 첫 위치가 필요하면 일반 탐색 대신 `lower_bound` 같은 경계 탐색을 써야 한다.

**확인 질문:** 목표를 `7`로 바꾸었을 때, `12`를 본 직후 어느 쪽 범위를 버려야 할까?

정답은 `12`가 `7`보다 크므로 오른쪽 범위 `4..6`을 버리는 것이다.

## 출처 연결

- 정렬 전제와 삽입 위치의 의미는 Python `bisect` 공식 문서의 `bisect_left`와 `bisect_right` 설명을 따른다.
- `lower_bound`와 `upper_bound`의 경계 표현은 cppreference 설명을 참고했다.
- 위 숫자별 인덱스와 결과는 이 문서와 함께 제공한 실행 가능한 순수 함수의 계산 결과다.
