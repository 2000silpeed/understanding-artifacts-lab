B 트리: 여러 키를 한 노드에 담아 탐색과 삽입하기 — 소스 패키지

AI 기본기 교육 영상(공개 패키징 트랙 15). 소스 단계다. 녹음·음악·렌더는 아직 없다(아래 "다음 단계").

구성: 핵심 개념 요약 → 구체적 사용 상황(데이터베이스 색인) → 본 강의 7장(노드 구조 · 탐색 · 삽입 · 분할 · 연쇄 분할 · 파이썬 코드 · C++17) → 정리·실습 → 엔드 카드. 장면별 화면 카피와 발화는 scenario.md, 컷 단위 계획은 shotlist.md.

한 번의 실제 실행이 원천이다

화면의 트리 상태, 탐색 경로, 비교 횟수, 층수, 코드 줄, 출력 줄은 모두 data/film-data.json에서 읽는다. 이 파일은 code/export.py가 Python 예제를 실제로 돌려 만들고, 같은 입력으로 C++ 예제를 컴파일·실행해 출력이 한 글자도 다르지 않은지 확인한 뒤에만 쓴다. 발화의 숫자는 voice/script.json의 claims로 같은 파일과 대조한다(테스트).

다음 단계 (승인 필요, 이 패키지에서는 하지 않음)

  1. 읽기 승인: voice/script.json의 readings 중 approve: true(k개·k+1개, C++17, 코드 이름 읽기).
  2. 목소리 고르기·녹음(유료): 후보 3–5개를 summary 첫 문장으로 비교 → 장면당 한 파일, tts 문장 그대로.

python3 pipeline/elevenlabs.py tts <voice_id> "<tts>" films/b-tree-20261108/voice/<file> --model eleven_v4 --stability 0.55 --style 0.2 --speed 0.95 파일 이름은 voice/script.json의 file(seg-01-summary.mp3 … seg-11-end.mp3).

  1. 전사: 장면마다 Scribe 결과를 voice/scribe/<scene>.json({"words": [{"text","start","end","type"}]})으로 둔다 → python3 films/b-tree-20261108/plan.py가 실측 단어 시각과 녹음 길이로 장면 길이·큐를 다시 쓴다(큐를 못 찾으면 어느 큐인지 알려 준다).
  2. 음악(유료): shots.json music.brief(100 BPM, 내레이션 밑 차분한 베드, 길이는 재계획 뒤 값) → films/b-tree-20261108/music/score.mp3 → pipeline/measure_music.py로 위상을 재서 plan.py의 offset에 적는다. 베드 0.6배, 내레이션 아래 12 dB 덕킹(film.js score).
  3. 스틸 게이트(사람 확인): node pipeline/build.cjs b-tree-20261108 && node pipeline/render.cjs b-tree-20261108 --format 16x9 --stills → contact.py 시트, 9:16도.
  4. 제작·검증: sh pipeline/make.sh b-tree-20261108 16x9 9x16 → verify.py PASS → shotlint.py b-tree-20261108 --video 16x9 9x16 → REVIEW.md. 기술 PASS는 승인이 아니다.

알려진 한계 (소스 단계)

  • 단어 시각과 길이(약 317초)는 추정값(초당 5.6음절)이다. 실제 녹음 뒤 바뀐다.
  • 레이아웃은 모의 캔버스(한글 0.95em·라틴 0.6em 근사)로만 검사했다. 실제 글자 폭·겹침·가독성은 스틸 게이트에서 눈으로 확인해야 한다.
  • 녹음과 음악 파일이 없어서 지금은 audio.py가 이 영상을 섞을 수 없다(목소리 큐가 voice/*.mp3를 가리킴).
  • 자체 호스팅 고정폭 서체가 없어 코드는 Pretendard를 고정 칸에 놓아 그린다(공유 폰트 설정은 바꾸지 않음).
  • paper 장면의 밝은 배경 필드는 움직임이 약해 QA "1초 이상 정지 구간"에 걸릴 수 있다. 렌더 뒤 확인이 필요하다.

B 트리: 여러 키를 한 노드에 담아 탐색과 삽입하기 — 시나리오

plan.py가 voice/script.json과 샷 계획에서 생성한다(직접 고치지 않는다).

  • 시리즈: AI 기본기 (공개 패키징 트랙 15 — 메타데이터만, 화면에는 쓰지 않음)
  • 형식: 한국어 내레이션 교육 영상, 설명형(배경 필드 + 헤드라인 + 다이어그램). 16:9 마스터, 9:16 재배치. 30fps. 총 316.8초(녹음 전 추정값(초당 5.6음절)).
  • 구성: 핵심 개념 요약 → 구체적 사용 상황 → 본 강의 7장 → 정리·실습 → 엔드.
  • 예제: 차수 5 B 트리(노드당 키 최대 4개, 루트 외 최소 2개). 입력 30 10 50 20 40 70 60 80 25, 탐색 40(있음)·65(없음).

사용 상황 수치도 같은 프로그램의 실제 실행값이다: 가득 찬 트리 기준 최소 층수(키 1개 20층 · 4개 9층 · 255개 3층), 키 1,000,000개 실험(3층, 읽은 노드 3개, 비교 279번). 노드당 255개는 페이지 크기를 가정한 설명용 선택이라 화면에 예시 값을 붙인다.

  • 사실 원천: data/film-data.json(code/export.py가 Python 실행에서 생성, C++ 출력과 같은지 확인). 화면의 숫자·트리·코드 줄·출력 줄은 모두 이 파일에서 읽는다.
  • 발화: voice/script.json — text(대본 원문), tts(숫자·영문·코드명을 한글로 읽기), cues(그림이 놓이는 단어), claims(발화 숫자 ↔ 실행값, tests/test_film_data.py가 대조).

연출 규칙

  • 장면마다 레시피 하나, cerulean ↔ paper 교대. 배경은 레시피 field 색의 FlowingGradient(구조 고정, 값만 변함).
  • 키는 값으로 식별한다. 한 단계(삽입·분할)는 이전 트리 → 다음 트리 모프: 새 키는 위에서 내려앉고(append), 남은 키는 비켜나고(transform), 새 노드는 자기 키가 있던 칸에서 자란다(split). 가운데 키는 위로 간다.
  • 등장은 그 단어가 들리는 프레임에 보이고 위치만 움직인다(rise). 도형과 글자는 같은 오프셋으로 움직인다.
  • 코드 패널: 자체 호스팅 고정폭 서체가 없어 Pretendard를 고정 칸(0.6em)에 놓는다(공유 폰트 설정은 바꾸지 않음). 코드 줄은 48열 이하.
  • 마지막 장면은 정지 락업(holdLast).
