# 이진 탐색 트리의 검색과 삽입 커리큘럼

## 선행 지식
- 숫자 비교와 반복문을 알고 있어요.
- 배열의 위치 번호가 0부터 시작한다는 점을 알고 있어요.
- 트리의 용어는 이 수업에서 루트부터 다시 정의해요.

## 새 용어와 정의
- **노드**는 값 하나와 자식으로 가는 연결을 담은 점이에요.
- **루트**는 트리의 가장 위 노드예요.
- 어떤 노드와 그 아래 모든 노드를 함께 **부분트리**라고 해요.
- 이진 탐색 트리, 즉 BST는 모든 노드에서 왼쪽 부분트리의 값이 노드보다 작고, 오른쪽 부분트리의 값이 노드보다 큰 규칙을 지켜요. 여기서는 중복을 넣지 않아요.
- 노드에서 내려갈 수 있는 가장 긴 경로의 길이를 높이라고 부를게요. 빈 트리의 높이는 이 수업의 코드에서 0으로 기록해요.

## 관찰 가능한 학습 목표
1. 주어진 BST에서 루트와 부모, 자식, 부분트리를 가리킬 수 있어요.
2. `[8,3,10,1,6,14,4,7,13]`을 순서대로 삽입한 결과를 설명할 수 있어요.
3. `7` 검색에서 `8 → 3 → 6 → 7`을 따라가는 이유를 말할 수 있어요.
4. 없는 `5`를 검색할 때 `8 → 3 → 6 → 4` 뒤 빈 왼쪽 자리에 도착하는 과정을 예측할 수 있어요.
5. 같은 위치에 이미 값이 있으면 중복을 무시하고, 빈 자리에만 삽입한다는 점을 구별해요.
6. BST의 부분트리 규칙이 최소 힙의 부모-자식 규칙과 다르다는 점을 설명해요.
7. 검색과 삽입이 높이 `O(h)`이고, 균형이 좋으면 `O(log n)`, 한쪽으로 치우치면 최악 `O(n)`임을 말할 수 있어요.
8. 삭제와 자동 균형화는 이 구현에 없고, 계측 트레이스의 배열 복사 비용은 자료구조 연산 비용과 별도라는 점을 확인해요.

## 고정 예시와 실행 계약
- 기본 삽입 입력: `[8,3,10,1,6,14,4,7,13]`
- 기본 트리의 검색: `7`은 `8 → 3 → 6 → 7`에서 발견해요.
- 없는 값 검색: `5`는 `8 → 3 → 6 → 4`를 거쳐 `4`의 왼쪽 빈 자리에 도착해요.
- 그 자리에 `5`를 삽입한 뒤 검색하면 `8 → 3 → 6 → 4 → 5`에서 발견해요.
- `5`를 다시 삽입하면 이미 존재하므로 트리는 변하지 않아요.
- 전이 입력은 `[5,2,8,1,3]`으로 두고 실제 실행 결과를 확인해요.
- 경계 입력은 빈 트리에서 검색과 삽입을 실행해요.

## 예측과 전이 질문
- 예측: `7`을 찾을 때 `8`에서 왼쪽, `3`에서 오른쪽, `6`에서 오른쪽으로 가는 이유는 무엇일까요?
- 예측: `5`가 없을 때 마지막으로 확인하는 노드는 무엇이고, 새 노드는 어느 쪽에 붙을까요?
- 전이: `[5,2,8,1,3]`에 `4`를 삽입하면 검색 경로는 어떻게 될까요?
- 전이 정답: `4`는 `5 → 2 → 3`에서 오른쪽 빈 자리에 삽입돼요.
- 비교 질문: 최소 힙은 부모와 자식 사이의 값만 제한하지만, BST는 각 노드의 왼쪽·오른쪽 부분트리 전체를 제한해요.

## 범위와 한계
- 핵심 구현은 노드, 검색, 삽입을 직접 만들어요. 내장 트리나 라이브러리로 대체하지 않아요.
- 삭제와 자동 균형화는 구현하지 않아요.
- 트레이스는 학습을 위해 각 단계의 경로와 노드 목록을 복사해요. 그 기록 비용은 검색·삽입의 이론적 `O(h)` 비용과 분리해서 설명해요.
