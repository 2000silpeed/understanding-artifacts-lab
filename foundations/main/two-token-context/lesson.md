# 두 토큰 문맥 연결

## 문제를 작게 고정하기
직전 토큰 하나만 보던 순방향을 두 토큰 창으로 늘려 볼게요. 토큰 표에는 `a`, `b`, `c` 세 토큰이 있고, ID는 0부터 세요. 임베딩 표 `E`는 세 행과 두 열이에요.

`E=[[1,0],[0,1],[1,1]]`

문맥 `[a,b]`는 첫 번째 행과 두 번째 행을 조회해요. 두 벡터를 이어 붙이면 `h=[1,0,0,1]`이고, 모양은 `1×4`가 돼요. 앞의 두 칸은 첫 번째 위치, 뒤의 두 칸은 두 번째 위치예요.

## 연결과 평균의 차이
순서를 바꾸면 `[b,a]`의 `h=[0,1,1,0]`가 돼요. 같은 두 벡터를 평균하면 두 순서 모두 `[0.5,0.5]`예요. 평균은 위치 정보를 지우지만 연결은 위치 블록을 보존해요. 연결이 항상 다른 출력이 된다는 뜻은 아니고, 출력 행렬이 두 경우를 같게 만들 수도 있어요.

## 고정된 출력 계산
출력 행렬 `W`는 `4×3`으로 고정해요.

`W=[[1,0,-1],[0,1,0],[0,-1,1],[1,0,0]]`

`[a,b]`에서는 각 출력 열을 따로 계산해요. 첫 열은 `1×1+0×0+0×0+1×1=2`, 둘째 열은 `1×0+0×1+0×-1+1×0=0`, 셋째 열은 `1×-1+0×0+0×1+1×0=-1`이에요. 그래서 `z=hW=[2,0,-1]`이고, `[b,a]`에서는 `z=[0,0,1]`이에요. 로짓은 아직 점수라서 확률이 아니에요. 안정적인 소프트맥스는 가장 큰 점수를 먼저 빼고 지수화한 뒤 합으로 나눠요.

## 미래를 보지 않는 학습 쌍
원문 시퀀스 `[a,b,c,a]`에서 길이 두 창을 한 칸씩 이동해요. 첫 쌍은 `[a,b]→c`, 다음 쌍은 `[b,c]→a`예요. 각 목표는 문맥 바로 다음 토큰이고, 목표 뒤에 있는 토큰은 현재 입력에 넣지 않아요. 이 예제는 순방향과 쌍 생성만 보여 주며 학습 루프는 만들지 않아요.

## 예측하고 전이하기
질문: `[b,a]`의 점수는 `[a,b]`와 같을까요? 화면에는 두 임베딩 행과 `W`를 남기고 답을 잠깐 숨겨요. [#pause] 이제 실제로 계산하면 순서에 따라 점수와 확률이 달라져요.

새 입력 `[c,a]`도 실행해요. `h=[1,1,1,0]`, `z=[1,0,0]`이 나와요. 문맥 길이를 늘리면 `h`와 `W`의 폭이 커지고 계산량도 늘지만, 고정 창 밖을 자동으로 기억하지는 않아요.

## 코드로 확인하기
두 프로그램은 프레임워크나 자동 미분 없이 같은 배열 연산을 실행해요. Python과 C++17 모두 출력 열과 입력 행을 도는 중첩 누적 루프를 실제로 실행해요. 먼저 기본 출력과 전이 결과를 보고, `--trace`로 각 피연산자, 곱, 부분합을 포함한 중간 상태를 JSON으로 비교해요.

```sh
python3 canonical.py
python3 canonical.py --trace
g++ -std=c++17 -Wall -Wextra -pedantic canonical.cpp -o /tmp/lesson-2026-10-20-llm
/tmp/lesson-2026-10-20-llm
```

마지막 규칙은 간단해요. 두 임베딩을 위치 블록으로 연결하고, 고정된 출력 행렬과 안정적인 소프트맥스로 다음 토큰 점수를 계산해요.
