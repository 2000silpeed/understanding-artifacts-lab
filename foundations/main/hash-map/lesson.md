# 해시 맵, 같은 바구니에 들어가면 어떻게 찾을까?

번호를 알면 과일 이름을 찾는 보관함을 만들어 봐요. 키는 찾는 기준인 번호이고, 값은 연결된 과일 이름이에요. 키와 값의 대응을 매핑이라고 해요. 배열은 알고 있는 위치를 바로 읽고, 연결 리스트는 항목을 따라가며 찾아요. 오늘의 해시 맵은 버킷을 먼저 고른 뒤 그 안을 탐색해요.

버킷은 항목을 나누어 담는 칸이에요. 네 개의 버킷에 0부터 3까지 번호를 붙여요. 비음수 정수 키만 허용하고, 음수는 버킷 계산 전에 거절해요. 나머지는 같은 크기의 묶음으로 나눈 뒤 남는 수예요. 6을 4로 나누면 2가 남아요. 코드에서는 `key % 4`가 이 나머지 계산이에요. 키에서 버킷 번호를 계산하는 규칙을 해시 규칙이라고 해요.

키 2와 6의 버킷을 먼저 예측해 보세요. 둘 다 나머지가 2예요. 서로 다른 키가 같은 버킷을 고르는 일을 충돌이라고 해요. 충돌은 중복 키가 생겼다는 뜻이나 값이 사라졌다는 증거가 아니에요. 버킷 안에 키와 값 쌍을 이어 놓는 체인을 두면 두 항목을 함께 보관할 수 있어요. 이것이 분리 연결법이에요. 그림은 논리 연결이고, 실제 코드는 각 버킷 안에서 작은 순차 목록을 사용해요.

실제 실행은 빈 맵에서 시작해요. `put(2,"사과")`는 버킷 2가 비어 있어 비교 없이 새 항목을 붙여요. `put(6,"배")`는 같은 버킷에서 2와 6을 비교해요. 다르므로 뒤에 6:배를 붙여요. `put(3,"귤")`은 버킷 3에 새 항목을 붙여요. 이제 버킷 2는 앞에서부터 2:사과, 6:배이고, 버킷 3은 3:귤이에요.

`get(6)`의 키 비교 횟수를 예측해 보세요. 버킷 선택 뒤 저장 키 2와 요청 키 6은 달라요. 다음 저장 키 6과 요청 키 6은 같아요. 키 동등성이란 두 키가 정확히 같은지 확인하는 조건이에요. 비교 두 번으로 배를 반환해요. 해시 계산은 이 키 비교 횟수와 별도예요. 조회는 맵을 바꾸지 않아요.

`put(6,"포도")`는 충돌 삽입일까요, 갱신일까요? 버킷 2에서 2와 6을 비교한 뒤 6과 6이 같은 것을 찾아요. 그 항목의 값만 포도로 바꿔요. 같은 키 6을 중복해서 붙이지 않아요. 다른 키가 같은 버킷에 가는 충돌과, 같은 키의 값을 바꾸는 갱신을 구별하세요.

`delete(2)`는 버킷 2 전체를 비우지 않아요. 첫 항목의 키 2가 요청 키 2와 같아서 비교 한 번으로 사과 항목만 지워요. 성공은 true예요. 키 6의 포도와 버킷 3의 귤은 남아요.

이제 `get(10)`의 결과를 예측해 보세요. 10을 4로 나눈 나머지는 2예요. 하지만 남은 저장 키 6은 요청 키 10과 달라요. 비교 한 번 뒤 체인이 끝나므로 없음(null)을 반환해요. 포도는 반환하지 않아요. 버킷이 같은 것과 키가 같은 것은 다른 조건이에요.

빈 버킷에서는 비교할 키가 없으니 비교 영 번으로 없음이에요. 없는 키의 삭제는 false이며 상태를 바꾸지 않아요. 음수 키도 상태를 바꾸지 않고 invalid_key로 거절해요. 별도 경계 실행은 빈 조회, 실패 삭제, 음수의 세 연산, 키 0과 4의 충돌·갱신·삭제를 확인해요.

실행 파일은 [canonical.py](canonical.py)와 [canonical.cpp](canonical.cpp)예요. 아래 명령은 네트워크나 외부 의존성이 필요 없어요.

```sh
python3 canonical.py
python3 canonical.py --trace
python3 canonical.py --edges --trace
g++ -std=c++17 -Wall -Wextra -pedantic canonical.cpp -o /tmp/hash-map-example
/tmp/hash-map-example --trace
node source-test.mjs
```

기본 출력은 `["inserted","inserted","inserted","배","updated",true,null]`이에요. [expected.txt](expected.txt)와 [trace.json](trace.json)은 Python의 실제 실행으로 생성했어요. 소스 테스트가 C++17 실제 실행 결과와 JSON 구조 및 기본 출력 바이트를 비교해요. 출력 JSON의 null은 Python 내부의 None을 직렬화한 결과예요. [lesson.html](lesson.html)은 같은 전체 기록을 포함하므로 파일로 열어 오프라인 연습할 수 있어요. 다음·예측·공개·초기화 및 연산별 선택을 제공해요.

시간 복잡도는 입력이 늘 때 작업량이 어떻게 늘어나는지 설명해요. 저장 항목 수를 n, 버킷당 평균 항목 수를 부하라고 해요. 적절한 분포와 일정한 범위의 부하 아래에서 평균 조회 O(1)을 기대할 수 있어요. 한 체인에 몰리면 최악 조회 O(n)이에요. 네 버킷을 고정한 예제는 계속 늘어나는 데이터에서 평균 상수 성능을 보장하지 않아요. 버킷 계산은 이 작은 정수 모델에서 일정한 작업이에요. 목록 중간 삭제에는 뒤 항목 이동도 있어요. 상태 스냅샷 복사와 JSON 기록 출력의 추가 비용은 이 알고리즘 설명에서 제외해요. 계측 프로그램 전체에 O(1)을 붙일 수는 없어요. 표준 Python dict나 C++ unordered_map이 이 장난감 구현과 같다는 주장은 하지 않아요.
