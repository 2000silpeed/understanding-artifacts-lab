# 깊이 우선 탐색 수업 커리큘럼

## 선행 지식
- 그래프를 정점과 간선의 연결로 읽고, 배열과 반복문을 사용할 수 있어요.
- 스택의 마지막 원소를 먼저 꺼내는 규칙을 이 수업에서 다시 정의해요.

## 핵심 정의
깊이 우선 탐색, {DFS|디 에프 에스}는 한 이웃을 따라 가능한 깊이 내려간 뒤, 더 내려갈 수 없을 때 돌아오는 그래프 탐색이에요. 이 수업은 재귀 대신 명시적 스택을 사용해요. 스택은 바닥에서 꼭대기 방향으로 왼쪽에서 오른쪽에 그리고, 오른쪽 끝을 먼저 꺼내요.

## 고정 데이터와 선택한 의미
기본 인접 리스트는 `A:[B,C], B:[A,D,E], C:[A,F], D:[B], E:[B,F], F:[C,E]`예요. 각 정점의 이웃은 적힌 순서가 우선이에요. 스택의 꼭대기에서 먼저 처리할 이웃이 적힌 순서대로 나오도록, 실제 push는 이웃을 역순으로 해요. 방문 표시는 push 순간에 하고, pop 순간이 아니라는 점을 고정해요.

정점을 꺼낸 뒤 이웃을 역순으로 살피며 아직 방문하지 않은 이웃을 표시하고 push해요. 명시적 스택에서는 선택한 새 형제들을 먼저 모두 표시하고 push하므로, 발견 순서가 재귀 DFS와 다를 수 있어요. 이 입력에서는 pop 순서가 같지만 그 사실을 일반 규칙으로 확대하면 안 돼요. 이미 표시된 이웃은 중복 push하지 않아요. 따라서 순서는 인접 리스트와 push 순서, 표시 시점의 합의 결과예요. 기본 그래프는 무방향 간선 6쌍, 인접 리스트 항목 12개예요.

## 관찰 가능한 학습 목표
- 정점, 간선, 이웃, 스택의 역할을 자신의 말로 설명해요.
- 기본 그래프의 전체 DFS 순서가 `A,B,D,E,F,C`임을 trace로 재현해요.
- target을 만났을 때의 조기 종료와 도달할 수 없는 target을 구별해요.
- 사이클에서 중복 후보를 보지만, push 시점 표시로 무한 반복을 막는 이유를 설명해요.
- DFS가 일반적으로 최단 경로를 보장하지 않는다는 점을 말해요.
- 알고리즘의 `O(V+E)`와 상태 snapshot을 남기는 계측 비용을 분리해요.

## 예측과 전이
- 기본 그래프에서 시작 A의 첫 pop 뒤 스택은 `[C,B]`이고, 다음 pop은 B예요.
- target F를 찾는 실행은 `A,B,D,E,F`까지 처리한 뒤 멈춰요. F는 E가 push할 때 표시되고, F를 pop하는 경계에서 성공을 선언해요.
- target Z는 어떤 이웃 목록에도 없으므로 전체 탐색 뒤에도 찾지 못해요.
- 대체 입력 `P:[Q,R], Q:[P,S], R:[P], S:[Q]`에서 P를 시작해 S를 찾는 실행도 실제로 수행해요. 결과는 `P,Q,S`예요.

## 비용과 범위
인접 리스트를 한 번씩 훑고 각 정점을 한 번만 push하므로 탐색 자체는 `O(V+E)`예요. 이벤트마다 전체 스택과 방문 집합을 복사해 JSON snapshot을 만들면 snapshot 하나의 비용이 추가돼요. 이 수업의 trace는 이해를 위한 계측이며, 알고리즘의 기본 비용과 같지 않아요.

재귀 DFS, 최단 경로, 가중치, 정렬, 자동으로 바뀌는 이웃 순서는 구현하지 않아요. 모든 화면과 설명은 수동으로 작성한 Python 및 C++17 실행 trace에 묶여 있어요.

## 전이 질문의 실제 답
대체 입력에서 P를 push하고, Q를 pop한 뒤 S를 push해요. S를 pop하는 순간 target을 찾으므로 처리 순서는 `P,Q,S`예요. P에서 R을 먼저 push하지 않는 것이 아니라, R은 Q보다 먼저 push되지만 LIFO 때문에 Q가 먼저 pop돼요. 이것이 인접 순서와 역순 push를 함께 설명해야 하는 이유예요.
