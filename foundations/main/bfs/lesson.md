# BFS 수업 원고

## 학습 목표
- 정점, 간선, 이웃, 무방향 그래프를 구별한다.
- 큐의 선입 선출과 삽입 시점 방문 표시를 설명한다.
- 거리와 경로를 간선 개수로 읽고, 도달 불가를 구별한다.
- 안정된 인접 순서로 Python과 C++17 실행 trace를 대조한다.

## 핵심 계약
그래프는 무방향이며 인접 목록은 `A: B,C`, `B: A,D`, `C: A,D,E`, `D: B,C,F`, `E: C,F`, `F: D,E`, `G: []` 순서다. `A`에서 시작해 `F`를 찾는다. 방문은 enqueue 때 표시하며, 거리는 시작점에서의 간선 수다. 방향 그래프는 별도 전이 문제로, 화살표의 나가는 이웃만 읽는다.

## 메커니즘
큐의 머리를 가리키는 `head`를 한 칸씩 움직인다. 이웃이 방문되지 않았을 때만 visited에 넣고 distance를 현재 거리 + 1로 기록한 뒤 큐 뒤에 넣는다. 큐는 먼저 들어온 층을 먼저 꺼내므로, 어떤 정점을 처음 발견할 때의 경로가 더 긴 경로보다 먼저 확정된다. 따라서 모든 간선의 비용이 같을 때 BFS의 거리는 최단 경로의 간선 수다. 가중치가 서로 다르면 큐의 순서만으로 최단 경로를 보장하지 않으므로 가중치에 맞는 다른 알고리즘이 필요하다.

## 이벤트 trace와 경로
각 기록은 하나의 enqueue, dequeue, 또는 이웃 skip 직후의 상태다. `queue`에는 head가 가리키는 미처리 suffix만 넣고, `visited`는 enqueue 순간 갱신한다. D를 dequeue할 때 F가 새로 enqueue되고, E를 처리할 때 F는 이미 방문되어 skip된다. parent를 `F → D → B → A`로 따라간 뒤 뒤집으면 `A → B → D → F`가 된다. trace의 snapshot 복사와 JSON 출력은 알고리즘의 `O(V+E)`에 포함하지 않는 계측 오버헤드다.

## 전이 질문
같은 그래프에서 시작점을 `C`로 바꾸고 목표를 `F`로 바꾸면 거리 `2`, 경로 `C → D → F`다. C와 F를 직접 잇는 간선은 없다. 방향 그래프에서 반대 방향 간선을 따라갈 수 없는 이유도 인접 목록과 방문 시점을 먼저 확인한 뒤 설명한다.
